### The purpose of SD-WAN

SD-WAN: A modern way of building the WAN.

SD-WAN uses:
- Centralized management
- secure overlays
- multiple transports
- application-aware decisions
- Segmentation
- Policies


---

### Traditional WAN Transport

The WAN was build using private cirtuits

- `MPLS` became popular because it provides predictable connectivity.
- Offered by service Providers
- Supports various classes of services
- Offers more controlled behavior than ordinary internet connectivity.


---

- MPLS solved a specific WAN problem very well.
- SD-WAN solves a different WAN problem.

---

### What changed?

- Applications moved to the cloud.
- Software as a Service (SaaS) applications and cloud hosted services can reside in multiple locations outside of the company datacenter.
- This change the traffic pattern.
- WAN designs build around centralized internet access
- Branch traffic --> DC --> Internet (Called as a Backhauling)
- Backhauling is inefficient:
  - Adds latency
  - Wastes bandwidth
  - poor user experience
- Traditional WAN was designed to optimize branch to data center traffic.
- Modern applications require branch to cloud traffic.


### Transport Technologies Changes.

- Availability of multiple transport options.
- Enterprise connectivity depended on a single private circuit.
- Broadband, fiber connections, 4G and 5G all become much more common and much more capable last-mile technologies.
- Branch could have multiple WAN links
- Why actively use only one link while keeping other link idle?

### The need for centralized Control Changed
- In traditional WAN, devices such as routers are individually configured.
- Routing decisions are made based on routing tables, metrics, and local configs.
- Policies, QoS and security rules may be configured on many different devices.
- Maintaining configuration harmonization becomes difficult and prone to errors.

### The importance of the applicaiton experiences
- Traditional routing is good to answering these questions?
  - Where is the destination?
  - What is the best path to get to the destination
- Morden WANs need additional questions answered:
  - What application is being served by this packet flow?
  - Voice? Video? File Transfer?
  - is it business critical?
  - is it guest traffic?
  - How healthy is the MPLS/Cable/5G/Fiber path now?
  - Is there any jitter, packet locss, or high latency?


> This is where SD-WAN adds value.

>> SD-WAN can consider the type of application being served by particular traffic, and the current state or quality of available paths to make real-time dynamic routing decisions.


- SD-WAN says: "For this application according to this policy, and based on the current path quality this is the preferred path at this point of time.

---

### Security:

- In the traditional model, the datacenter was the central security point
- Backhauling allowed security policies to be applied at one central location.
- Security Options: local firewall, cloud security service, is the traffic segmented, are users and apps treated different and how are policies applied?

**How does SD-WAN respond to these changes?**

- When applications move to the cloud, SD-WAN allows traffic to go `directly to the cloud` and Sass applications instead of `backhauling`.
- With multiple transport options, SD-wan uses those links more intelligently and efficiently.
- When the WAN becomes `header manage device to device`, SD-WAN provides centralized management and control.
- When application experience becomes more important, SD-WAN make forwarding decisions based on application type and the health of available paths.
- When `security` must be applied in more places, SD-WAN helps by combining segment, policy, secure tunnels, and integration with security services.


> SD-WAN is not simply a replacement for MPLS, but a response to a different WAN reality.

Yes, open-source SD-WAN projects and centralized management platforms do exist, though they are much less common than commercial offerings (like Cisco Viptela, VMware VeloCloud, or Fortinet) because traditional WAN tech relies heavily on proprietary hardware and ASIC optimizations.

The most prominent open-source project combining an SD-WAN edge software stack with a centralized management controller is **flexiWAN**.

---

### **1. flexiWAN (The Leading Open-Source SD-WAN & Centralized Controller)**

* **Overview:** Billed as the world's first open-source SD-WAN and SASE solution, **flexiWAN** decouples the centralized management and control logic from the edge data-plane routing software.
* **Centralized Management Controller (`flexiManage`):**
* Acts as the single pane of glass for provisioning, device monitoring, and configuration.
* Handles zero-touch provisioning (ZTP), full-mesh or hub-and-spoke tunnel orchestrations, and traffic steering policies with just a few clicks.
* Can be hosted in the cloud or self-hosted.


* **Edge Software (`flexiEdge`):**
* Installed on "Bring Your Own Hardware" (BYOH) x86 white-box appliances, VMs, or cloud instances (AWS, Azure).
* Built using a modular architecture where routing, tunneling, and security applications can be dynamically plugged in.



---

### **2. Alternative Software-Defined & Overlay Networking Stacks**

If you want to assemble your own open-source control-plane and edge architecture from granular components (similar to building a custom data center or cloud-native routing fabric), you can combine these tools:

* **OpenDaylight (The Centralized SDN Controller Engine):**
* An enterprise-grade, model-driven open-source SDN controller framework.
* It uses **NETCONF/YANG** and **BGP/PCEP** to provide centralized, programmable control and topology discovery. While it requires significant custom engineering to build a turnkey SD-WAN out of the box, it is widely used by telecommunications operators for advanced path computation and carrier-grade WAN automation.


* **VyOS + External Automation (The Open-Source Router Edge):**
* **VyOS** is an open-source, enterprise-grade network operating system (based on Debian) that supports advanced routing (BGP, OSPF, ISIS), firewalling, and tunneling (WireGuard, VXLAN, IPsec).
* While VyOS itself does not include a proprietary multi-tenant central manager like commercial SD-WANs, it features full **REST APIs** and **NETCONF** interfaces, allowing you to build or tie it into a centralized automation framework (like Ansible or a custom Python controller).



---

### **Verification & Next Steps**

If you are deploying a lab to test open-source SD-WAN capabilities, downloading and setting up a basic **flexiWAN** environment (registering a central `flexiManage` instance and connecting a couple of Linux VM edge nodes via `flexiEdge`) is the fastest way to experience an open-source centralized control loop in action.
